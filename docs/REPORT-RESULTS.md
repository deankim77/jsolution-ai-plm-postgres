# 보고 · 회의 결과 목록

- 프로젝트 목록·MY WORK와 같은 `V2ListTable`, `useColumnFilters`, `CommonProjectSelector`를 사용한다.
- 제목 아래 조회 도구에서 프로젝트를 변경하거나 전체 프로젝트를 조회한다. 개별 프로젝트 선택은 상단 프로젝트 문맥에도 반영된다.
- 주간보고서·회의 안건·Baseline 일정 분석을 하나의 목록에 표시한다. 본문은 행을 열 때만 조회한다.
- 현재 계정 소유의 서버 보고 결과(기존 AI 응답·자동 주간보고)를 사용한다. 다른 사용자의 개인 AI 대화를 공개하지 않는다.
- 기존 보고서는 첫 요청과 프로젝트 문맥으로 분류한다. 예전 자료의 미저장 보고 기간은 `기간 미지정`으로 표시한다.
- 새 보고서는 `보고서:weekly`, `보고서:meeting`, `보고서:schedule` 문맥에 프로젝트 ID와 보고 기간을 남긴다. 별도 DB 스키마나 시드 실행은 필요 없다.
- 회의 안건·Baseline 분석은 보고 기간·포함 자료 선택 → 요약 자료 확인 → 명시적인 `AI 작성` 순서로 실행한다. 주간보고서는 아래 자동 작성 흐름을 사용한다. 자료 준비·목록·미리보기·다운로드에서는 AI를 호출하지 않는다.
- 보고 기간의 실적은 날짜 조건으로 DB에서 읽는다. 현재 진척·열린 이슈·산출물 상태는 현재 스냅샷임을 구분한다.
- AI 분석 유형의 전송 업무 문맥은 최대 8,000자로 제한하고 문서 원문을 자동 첨부하지 않는다. 이 제한은 시스템 프롬프트 등을 포함한 전체 입력 토큰 한도가 아니다.
- 결과 생성 후 목록을 갱신한다. 저장된 PPT 또는 문서 미리보기·다운로드는 기존 공통 기능을 재사용한다.

검증: `node --test tests/report-results.test.mjs tests/report-results-service.test.mjs`

## 저장 데이터 기반 주간보고서

- 주간보고서는 프로젝트·보고 기간(최대 7일)을 선택하고 생성한다. 기존 5개 자료 체크박스는 회의 안건·Baseline AI 분석에만 사용한다.
- 주간보고는 ① 전체 요약 ② 금주 진행·완료 ③ 누적 지연·Baseline 변경 ④ 미해결 이슈·리스크·협조 ⑤ 산출물 제출 ⑥ 차주 계획 ⑦ PM 확인·지원 요청의 7개 항목을 항상 작성한다.
- `/api/reports/weekly` → Service → Repository → Drizzle/PostgreSQL에서 처리하며 외부 AI 호출·문서 원문 전송은 없다. 회사·프로젝트 접근 권한을 검사한다.
- 프로젝트 데이터를 하나의 repeatable-read 스냅샷으로 읽는다. 완료 여부 등은 생성 시점 상태, 실적·리비전은 보고 기간 기준이다. 과거 시점 상태를 복원하지 않음을 보고서에 명시한다.
- 계획 진척률은 프로젝트 대시보드와 같은 공통 함수(실행 Task 동일 가중, 현 계획 일정의 달력일 선형 진척)를 사용한다. 날짜가 빠지면 산정 불가로 표시한다. 지연일수·미해결 경과일은 달력일, 날짜 변환은 한국 시간 기준이다.
- 산출물 자체 제출 예정일 필드가 없으므로 연결 업무 종료일을 사용하고 이 기준을 표시한다. 등록 리비전 metadata만 조회한다. 지연 사유·조치 계획을 추정하지 않고 최근 실적·관련 미해결 항목을 함께 제시한다.
- 생성 결과는 기존 보고 결과 저장소(ai_conversations/ai_messages)에 `주간보고서 자동 작성 · AI 미사용` 출처로 원자적으로 저장한다. 목록 범위는 기존과 동일하게 현재 계정이다. DB 마이그레이션 불필요.
- 미리보기·PPT 다운로드는 같은 슬라이드 구분을 사용한다. 상세가 많으면 후속 슬라이드를 추가하며 전체 본문을 한 장으로 자르지 않는다.
- 작성 패널은 기존 업무 패널과 같은 `WorkPanelFrame`을 사용하고 확장폭으로 열어 축소·확장할 수 있다. 설정용 패널을 사용하지 않는다.

검증: `node --test tests/weekly-report.test.mjs tests/report-results.test.mjs tests/report-results-service.test.mjs`
