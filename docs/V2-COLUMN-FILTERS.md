# V2 목록의 열 필터

프로젝트 목록·내 업무와 같은 공통 멀티 선택 팝오버를 다음 실제 목록 렌더러에 적용한다.

| 화면 | 열 필터 |
| --- | --- |
| 프로젝트·내 업무 Workflow | 유형, 프로젝트, 결재선, 현재 단계·처리자, 기한, 상태 |
| 이슈·리스크·협업 | 구분, 프로젝트, 중요도, 담당자, 상태. 기한 범위는 기존 상세 필터와 연결 |
| 문서·도면 라이브러리 | 카테고리, 프로젝트, 작성자, Revision, 상태 |
| 일정·WBS 목록 | 구분, 시작·종료 기간, 담당, 산출물·이슈 유무, 진척 구간, 상태 |
| 설계변경·품질관리 | 프로젝트, 현재 단계·처리자, 유형, 기한, 상태 |
| PART 라이브러리 | Item Role, Revision, 단위, BOM 구조 유무 |
| 프로젝트 비용 실적 | 발생 기간, 카테고리, Task, 업체, 등록자 |
| 조직·사용자·권한·거래처 기준정보 | 분류·연결정보, 사용 상태 |
| 공통코드·산출물 카테고리 | 코드, 문서분류, 업무영역, 사용 상태 |
| 감사 이력 | 기간, 작업, 대상 유형, 사용자 |

- `V2ColumnMultiFilter` / `V2ColumnDateFilter`를 재사용한다. 열 버튼은 우측 패널을 열지 않는다.
- 체크 상태는 적용할 때 반영한다. 취소·Escape·바깥 클릭은 적용하지 않는다. 전체 선택은 조건 해제다.
- 한 열에서 여러 값은 OR, 다른 열 및 기존 검색·상세 조건과는 AND로 조합한다.
- 전체 데이터가 내려오는 목록은 `useColumnFilters`를 사용한다. 후보는 열 필터 적용 전 입력에서 구하며, 결과가 없어도 헤더와 해제 기능을 유지한다.
- 이슈는 `projectIds`, `types`, `statuses`, `owners`를 서버로 보내 페이지 제한 전에 처리한다. JSON 배열은 쉼표가 있는 이름을 보존하며 기존 단일 조건도 지원한다. 접근 권한과 회사 범위를 유지하고 같은 조건으로 총 건수를 계산한다.
- WBS 필터는 부모의 기존 계층 계산에 연결해 상위 Gate를 유지한다. 편집 전용 화면, BOM 트리와 원가 합계 표에는 행을 감추는 필터를 추가하지 않는다.
- 좁은 화면은 표의 가로 스크롤과 공통 팝오버의 화면 안 위치 조정으로 처리한다.

검증: `node --test tests/remaining-column-filters.test.mjs tests/project-mywork-lists.test.mjs tests/my-work-multi-filter.test.mjs`, `npm run check:architecture`, `npm run check:v2-ui`, `npm run audit:react-dom`.
